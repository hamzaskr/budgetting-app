# Ledger UX guidelines

- Keep the common path short: amount, sensible source default, optional category, and save.
- Group fields by task and keep labels, controls, helper text, and errors adjacent.
- Use progressive disclosure for transfer destination and advanced planning options.
- Preserve form values after domain or exchange-rate failures.
- Use direct labels such as “Last confirmed”, “Amount remaining”, and “Display currency”.
- Keep one primary action per form or section.
- Use confirmation for reset/import replacement and avoid confirmation for ordinary entries.
- Never send financial data to the exchange-rate provider; only public rate tables are requested.
- Test every screen at 320px, 390px, 768px, 1024px, and 1440px widths, including overflow and sheet bounds.
